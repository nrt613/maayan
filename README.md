# מעיין — יומן טהרת המשפחה

אפליקציה חינמית ופרטית ליומן טהרת המשפחה: רישום, חישוב עונות הפרישה, שבעה נקיים, ליל הטבילה ותזכורות. אין חשבון ואין שרת. היומן נשמר רק במכשיר של המשתמשת (localStorage), והאפליקציה המותקנת אינה פונה לרשת בכלל (באנדרואיד אין אפילו הרשאת INTERNET).

**גרסת בדיקה לבודקים הלכתיים. החישובים טרם קיבלו אישור הלכתי.**

## מה יש באפליקציה
- **היום:** כרטיס המצב (ממתינה להפסק, יום N מתוך 7 עם טבעת התקדמות, ליל הטבילה) והמועד הבא, נקודות לבירור (אם יש), מועדים קרובים וזמני היום (זריחה, שקיעה, צאת הכוכבים).
- **הכנות לטבילה:** רשימת הכנה שנפתחת מליל הטבילה: במסך היום ביום השביעי ובליל הטבילה, ובמועד ״ליל טבילה״ במועדים ובלוח.
- **רישום מהיר:** כפתור ״רישום״ צף מעל סרגל הלשוניות פותח בלחיצה אחת תפריט מהיר (ראייה, הפסק, בדיקה, טבילה, אחר). בלוח השנה הוא רושם ליום שנבחר, ולחיצה ארוכה על יום פותחת את התפריט לאותו יום.
- **לוח השנה:** לועזי או עברי, ניווט בין חודשים ושנים, צביעת ימי וסת, שבעה נקיים, עונות פרישה, אור זרוע וטבילה.
- **היומן שלי:** כל הרישומים (ביומן ארוך — בהדרגה), חיפוש וסינון, הזנת מחזורים קודמים, ו״דוח לבירור״ בטקסט גלוי למורה הוראה.
- **מועדים:** כל המועדים המחושבים עם הכלל והמקור, ייצוא קובץ ‎.ics, והתראות (באפליקציה המותקנת — גם כשהיא סגורה).
- **שיטות מוכנות, בבחירה בשני שלבים:** ״מה המנהג שלך?״ — ספרדי, אשכנזי או חב״ד; ואז ״לפי מי?״: לספרדים **הרב עובדיה יוסף** (בלי אור זרוע, לפי טהרת הבית) או **בן איש חי** (עם אור זרוע, בן איש חי שנה ב, צו, א); לאשכנזים **עיקר הדין** (עונה בינונית בימים 30 ו-31, עונה אחת — עונת הראייה, אור זרוע לפי הש״ך — מסומן לבירור מול הט״ז) או **כרתי ופלתי** (עונה בינונית יממה שלמה בימים 30 ו-31, ושימור הפלגה ארוכה כרמ״א קפט, יג והט״ז). בחב״ד אין שלב שני. בכל השיטות פרט לכרתי ופלתי וחב״ד הפלגה ארוכה נעקרת מיד (ב״ח, ש״ך). כל שאר ההגדרות (המתנה של 4 או 5 ימים, הפסק אחרי השקיעה בדיעבד לשיטת הרב עובדיה, צאת הכוכבים, בין השמשות ועוד) נקבעות לפי השיטה, ואפשר לשנות כל אחת תחת ״התאמה אישית לפי הוראת הרב״, שמראה כמה הגדרות שונו מהשיטה. בממשק כל שיטה מוצגת בשמה ובשורה אחת קצרה, בלי מקורות ובלי אזהרות; הפירוט, המקורות והמחלוקות לכל ערך נמצאים במסמכי הרב (`docs/halacha/`). יומן שנשמר בגרסה קודמת עם ״מנהג אשכנז הרווח״ שומר את ערכיו ומוצג כ״אשכנזי – עיקר הדין״ עם השינויים מהשיטה.
- **״יש לשאול רב״:** השיטות סופיות. בשאלות שנשארו פתוחות המנוע אינו מכריע בשקט: כשהמצב נוצר ביומן מופיעה נקודה ״יש לשאול רב״ (במסך היום ובנקודות לבירור), בסגנון רגוע: משפט אחד שמתאר את המצב ומשפט אחד על מה שמעיין עושה בינתיים (לחומרא), בלי מקורות ובלי שמות דעות — אלה במסמכי הרב ובדוח לבירור. כך: ראייה בל׳ כשהחודש הבא חסר או מלא; הפלגה ארוכה שנעקרה בהפלגה קצרה ממנה (בשיטות בלי שימור, עם התאריך שבמחלוקת); ראייה שנמצאה בבדיקה או בהתעוררות (סימון בטופס — חוששים לשתי העונות של היום); ואור זרוע ביום 29 לפני עונה בינונית של מעת לעת בכרתי ופלתי. אור זרוע ליום 31 אינו מסומן — זו בחירת שיטה מתועדת.
- **פרטיות:** נעילה בקוד של 4–6 ספרות (נשמר רק גיבוב PBKDF2 עם מלח), טביעת אצבע / Face ID, נעילה מיד או אחרי יציאה, השהיה הולכת וגדלה אחרי ניסיונות שגויים, הסתרת התוכן במסך האפליקציות האחרונות באנדרואיד, כפתור ״הסתרת היומן״, ונוסח דיסקרטי לתזכורות (ברירת מחדל).
- **גיבוי:** גיבוי מוצפן בסיסמה (AES-GCM עם PBKDF2) לקובץ או לטקסט, שחזור בכל מכשיר, ותזכורת עדינה לגיבוי. מחיקת כל הנתונים מההגדרות (וגם מ״שכחתי את הקוד״).
- **וידג׳ט באנדרואיד:** כבוי כברירת מחדל, דיסקרטי כברירת מחדל ותמיד דיסקרטי כשהנעילה פעילה. השורות מחושבות מראש לשלושה ימים, כך שהווידג׳ט מתעדכן גם כשהאפליקציה סגורה.
- **שפות:** עברית (מקור), אנגלית, צרפתית וספרדית, כולל כיוון משמאל לימין.
- **לבודקים:** יומן לדוגמה, תרחישים מוכנים בזמן מדומה, הרצת בדיקות המנוע בתוך האפליקציה, כללי החישוב ומקורותיהם, והעתקת דוח עם הערות.

## מבנה המאגר
- `src/` — קוד המקור:
  - `core.js` — לוח עברי, זמני שמש (NOAA) ומנוע החישוב.
  - `app.js` — הממשק והאייקונים (SVG בקוד). `styles.css` — העיצוב: כל הצבעים, הרדיוסים והצללים כטוקנים ב-`:root`.
  - `i18n.js`, `i18n-dict.js` — תרגום (המקור בעברית, המילון לשאר השפות).
  - `tests.js` — בדיקות המנוע (רצות ב-Node ובתוך האפליקציה). `scenarios.js` — תרחישים לבודקים.
  - `widget.js` — סיכום הווידג׳ט לאנדרואיד. הצד הנייטיבי ב-`android/widget/`, ומוזרק ב-`android/prepare.py`.
- `fonts/` — הגופן Rubik (משתנה, OFL) בשלושה קובצי woff2 (עברית, לטינית, לטינית מורחבת). Heebo ו-Bellefair נשארים רק למפרט ההלכתי.
- `brand/icon.py` — מייצר את הסמל, מסך הפתיחה והלוגו הלבן (`brand/out/`), ומשם מעתיקים ל-`icons/`, `android/res`, `android/splash.png` ו-`ios/assets`.
- `index.html` — האפליקציה המלאה בקובץ אחד. **נבנית** מ-`src/`; לא עורכים אותה ידנית.
- `verify.js` — בדיקה עצמאית רחבה מול לוח עברי חיצוני (ICU) ומול אלגוריתם שמש שני.
- `tests/widget.test.js` — בדיקות הווידג׳ט.
- `android/` — עטיפת Capacitor 8 לאנדרואיד: `prepare.py` יוצר את הפרויקט בזמן הבנייה; `widget/`, `lock/` (FLAG_SECURE), `e2e/` (בדיקות באמולטור), `signing/`.
- `ios/` — עטיפת Capacitor 8 ל-iPhone (`prepare.py`, `assets/`).
- `docs/halacha/` — מפרט הלכתי לבדיקת רב (HTML ו-PDF), שנוצר אוטומטית מהמנוע.
- `store/` — טקסטים, תשובות לטפסים, צילומי מסך ורשימת משימות לחנויות: `CHECKLIST.md`, `declarations.md`, `listing.md`, `review-notes.md`, `screenshots.js`, `compare/`.
- `privacy.html` — מדיניות הפרטיות (מתפרסמת ב-GitHub Pages מ-`main`).
- `windows/`, `download/` — מתקין Windows שעובד בלי אינטרנט.

## בנייה
```
python3 build.py && cp dist/maayan.html index.html && rm -rf dist
```
`build.py` צריך את `brand/out/icon-32.png`. אם הקובץ חסר, מפענחים אותו מה-favicon (‏data URI של `<link rel="icon">`) שב-`index.html` הקיים.
אחרי כל שינוי ב-`src/` בונים מחדש ומכניסים את `index.html` לאותו commit.

## בדיקות
מריצים את שלושתן לפני כל דחיפה:
```
node -e 'const M=require("./src/core.js");console.log(require("./src/tests.js")(M).run().filter(t=>!t.ok))'   # → []
node verify.js              # כ-168,000 השוואות → failures: 0
node tests/widget.test.js   # דיסקרטיות, נעילה, שפות ותרחישים בסיכום הווידג׳ט
```
- כל שינוי ב-`src/core.js` מתחיל בבדיקה נכשלת ב-`src/tests.js`, ורק אחר כך התיקון. לא משנים התנהגות הלכתית או ערכי שיטות בלי הוראה.
- אותן בדיקות המנוע רצות גם במכשיר: הגדרות ← מסך הבודקים ← ״הרצה״.
- באנדרואיד ה-workflow מריץ בדיקת קצה-לקצה על אמולטור (`android/e2e/`): התראות, מיקום, שמירה, נעילה ו-FLAG_SECURE, וידג׳ט, ושאין שום פנייה לרשת. ב-iOS ה-workflow בונה ובודק בסימולטור.

## המפרט ההלכתי
```
node docs/halacha/build.js            # halacha.html ו-halacha.pdf
node docs/halacha/build.js --no-pdf   # HTML בלבד
```
המסמך נוצר מהמנוע עצמו (טבלאות השיטות, ההגדרות, נקודות הבירור והדוגמאות). אחרי שינוי ב-`src/core.js` מריצים אותו מחדש ומכניסים אותו ב-commit נפרד, אחרי ה-commit של המנוע, כך שהשער מציג commit נקי.

## הפצה ושחרור
- **GitHub Actions:**
  - `android-app` — רץ כשמשתנים `index.html`, `android/` או `fonts/` (ובהפעלה ידנית). בודק את הווידג׳ט, בונה APK ו-AAB, חותם (`SIGNING_PASSWORD`) ומריץ את הבדיקות באמולטור. ב-`main` גם מפרסם את `maayan.apk` ב-Releases.
  - `ios-app` — רץ כשמשתנים `index.html`, `ios/`, `fonts/` או `android/prepare.py`. בונה ב-Xcode 26 ובודק בסימולטור. העלאה ל-TestFlight: Actions ← ios-app ← Run workflow ← לסמן `testflight` (דורש את סודות App Store Connect).
  - `windows-installer-test` — בודק את המתקין ל-Windows.
- **מספרי גרסה:** `versionCode` = מספר הריצה ועוד `VERSION_CODE_OFFSET` (אם הוגדר). `versionName` = הגרסה הראשית והמשנית מ-`android/package.json` ועוד מספר הריצה; ב-iOS לפי `ios/package.json`.
- **Google Play:** מורידים את `maayan.aab` מה-Artifacts של הריצה (`maayan-android-<מספר>`) ומעלים כ-release חדש.
- **App Store:** מריצים את ios-app עם testflight, מוסיפים את הבנייה לגרסה חדשה ב-App Store Connect ומגישים.
- אם העיצוב השתנה: `node store/screenshots.js` (דורש Playwright) ומעלים את הצילומים החדשים.
- הצעדים הידניים (חשבונות, טפסים, הצהרות) ב-`store/CHECKLIST.md`, והתשובות לטפסים ב-`store/declarations.md`.

## התקנה במחשב Windows בלי אינטרנט
`download/Maayan-Setup.exe` — לחיצה כפולה מתקינה את מעיין עם אייקון בשולחן העבודה ובתפריט התחל. קוד המקור ב-`windows/` (נבנה ב-Go: `llvm-windres` למשאבים ואז `GOOS=windows go build -ldflags "-H windowsgui"`).
